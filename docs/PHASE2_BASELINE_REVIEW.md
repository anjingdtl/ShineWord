## 3. 建议的架构方向

小说原文 → 带证据的 Canon → 世界规则映射 → 版本化世界规则包 → 三宝书视图 → 独立战役及分支运行状态。

三宝书共享同一套结构化定义与引用，不各自生成互相独立的数值。规则引擎消费受限数据定义，阅读页面呈现对应说明。叙事文本不能成为规则执行程序。

| 书籍 | 建议职责 |
|---|---|
| 玩家手册 | 玩家可知的世界概览、角色创建、出身/职业或修行路径、属性与技能、行动、装备、能力、成长、探索与战斗基本规则 |
| 城主指南 | 世界硬规则、时间线与开局锚点、势力目标、秘密与揭露条件、场景/任务/遭遇编排、裁定模板、奖励、失败与世界响应 |
| 怪物图鉴 | 生物与对手模板，包括人类敌手；能力、资源、攻击、防御、行为目标、战术、生态、掉落和证据。不等于所有 NPC 都是敌人 |

玩家、同伴、重要 NPC 和敌人共享 Actor 模型；普通路人可以使用简化模板，但参与有后果的行动前必须冻结所需属性，不能看到骰点后补数值。怪物模板实例化后拥有独立资源与状态；唯一原著人物须限制重复实例。

每个游戏需要拥有：原文与世界包版本引用、规则包版本、开局设定、队伍、角色实例、地点与场景、任务与线索、遭遇、时间与资源、关系与认知、行动事件日志、快照和分支。不可变原文与规则包允许共享存储；游戏状态严格隔离。

运行循环应覆盖探索、社交、战斗、休整与成长。AI 提出行动和叙事，本地负责资格、行动成本、检定、效果与结算。秘密检索和公开叙事分通道；玩家阅读图鉴也需要按开局与遭遇知识过滤。

小说构建须区分：原文明示、证据归纳、规则映射、设计补全、用户覆写。关键硬规则冲突阻止发布；一般未知字段显示待补全或使用明确标注的规则默认值。开局后锁定版本，重新生成不覆盖进行中的游戏。
