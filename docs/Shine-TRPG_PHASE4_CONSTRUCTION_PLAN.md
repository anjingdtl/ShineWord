## 1. 产品目标与本期结论

Shine-TRPG 要成为**手机上轻松游玩的文字 TRPG**：读一段故事，选择或写下自己的行动，得到有规则依据的故事变化。玩家决定目标、态度和关键取舍；应用处理检定、轮转、同伴行动与状态记账。调查、解谜、交谈、日常、探索与战斗均使用同一个文字入口。

本期必须同时完成阅读界面收敛与行动链路简化。不能仅隐藏 HUD，却仍要求用户理解先攻、距离带、主要行动、标准移动；也不能把这些规则全部交给 LLM 自由发挥。规则继续有效，操作成本由应用承担。

交付对象是原有 React Native Android 应用，不创建网页替代品、不重写为聊天机器人、不另建图形战斗模式。文字体验仍具备角色、检定、代价、知识边界、持久状态和可恢复的分支历史。

### 1.1 成功体验

1. 打开已有故事，主要空间展示当前处境与已发生的叙事。
2. 点击一个文字行动后直接提交，或输入自己的话再点一次“行动”。
3. 需要澄清时回答一个必要问题；普通合法选择不经过重复确认。
4. 应用自动完成对应规则操作、非玩家轮转并显示结果，在下一个玩家决策点停下。
5. 随时查看人物、线索、随身物品与检定依据；无需打开这些资料也能继续主要故事。

“自动化”的范围是执行与记账；不会自动替玩家决定攻击谁、相信谁、交出重要物品、休息多久、领取何种成长、是否撤退或解谜答案。

## 5. 信息架构与阅读界面

### 5.1 默认游玩屏

纵向顺序：简短页头 → 故事正文（唯一主滚动区）→ 至多三条文字选择 → 紧凑自由输入。页头仅显示故事标题与“更多”；地点/时间可并入最近一段处境摘要。

正文由以下类型组成，均为文本，不要求气泡和卡片：

1. 场景：玩家当下可知的处境。
2. 你的行动：来自已持久化输入/合同的真实文字。
3. 故事结果：Narrator 已提交文本，或本地已提交事件的可见事实摘要。
4. 判定摘要：如“观察成功，你注意到窗沿的泥痕”，可展开骰点依据。
5. 重要变化：如“同行者受伤”“线索已记入记录”；仅状态改变时出现。

普通检定和战斗使用同一种正文排版。战斗中显示“门外的守卫逼近，你仍有退路”等**已知事实**，不显示棋盘。结果模板不得捏造原著事实、未授权谈判成功、未知身份或隐藏属性。

### 5.2 阅读约束（本期新验收指标）

| 条目 | 门禁 |
|---|---|
| 标准视口 | Android 360×800dp 与 412×915dp，键盘收起，默认字体缩放 |
| 正文占比 | 正文列表可视高度 / 扣除系统安全区后的页面高度 ≥60%；探索与战斗都需通过 |
| 小屏 | 320×640dp 正文可视高度 ≥45%；不得横向滚屏或挤没正文 |
| 键盘弹出 | 输入与提交可见；至少最近一段结果或局面摘要可读；不强求 60% |
| 正文字号 | 默认 17sp，用户可调 16～22sp；行高约 1.5～1.7；测系统 1.3×及 2×缩放不截断关键操作 |
| 操作数量 | 默认最多 3 条上下文文字选项、1 个自由输入提交；资料/菜单是导航，不混作行动 |
| 默认主屏禁入 | zone 格子、先攻条、血条矩阵、actor×zone 按钮、手动 NPC 推进、内部 ID/stateVersion |
| 可访问性 | 普通文字 ≥4.5:1，实际点击面 ≥44×44dp，读屏名称与焦点顺序明确，不能只靠颜色表达 |
| 主题 | 四主题只改变阅读配色和轻微排版强调；不出现遮字纹理/科技仪表/大头像 |
| 长历史 | FlatList 分页/虚拟化，≥100 条基线；阅读旧内容时新增结果不抢滚动，提供“有新内容”入口 |

60% 以布局测量和截图标注证明，不能根据肉眼估算。字体放大时允许选择区折叠为“选择行动”，保持入口可达，不强压字号。不要使用固定屏幕百分比把正文与键盘硬挤在一起。

### 5.3 次级入口

- **人物**：自己、当前同行者、可见 NPC 的文字档案；完整角色数值和检定训练依据按需展开。异常状态在正文主动提醒，不能隐藏濒危或失能。
- **记录**：当前目标、已知事实/线索、人物关系、未解决的问题；无任务时不强造任务。标题“线索”只在有资料时显示。
- **随身物品**：仅当前角色有权查看的物品；转移/使用保留本地资格检查。
- **更多**：休息、训练、同伴偏好、阅读设置、存档、回退、退出。休息/训练涉及时间或资源消耗，应显示代价并由用户选择。
- **检定依据/局面详情**：文字列表展示真实骰点、距离描述和先后顺序；默认只读。无需维护另一套正式图形战斗模式。旧 HUD 可暂置 Debug 回归入口，Release 不暴露调试控制。

## 6. 开局与首次游玩

### 6.1 快速开局默认两步

1. **选择身份**：原著角色（有公开可用模板时）/原创角色；原创只必填名字，其余使用本地合法推荐。无需强选同伴、技能和战斗定位。
2. **确认开始**：起点、人物短描述、可选目标、所选同行者；一个“开始故事”按钮；“自定义”可展开高级字段。

推荐值必须由现有建卡规则与世界 catalog 派生并验证：总属性点、单项上限、三技能合法性、能力准备与角色资格不变。若当前 API 仍要求三技能，使用当前世界可用技能构造合法默认并允许修改；不能伪造 martial/perception 等未定义技能。候选不足时明确返回构建诊断，不补不存在的内容来凑数。

同伴默认不强制招募；已选择同伴的偏好展示为人话，底层仍映射已有 directive 枚举，不新造无实现的“聪明行动”策略。原四步向导保留为自定义编辑能力，不能作为普通用户必经门槛。

### 6.2 导入状态

书库只强调“导入小说”“继续故事”。构建技术细节进入详情；真实状态使用“正在准备开篇”“开篇可玩，其他资料按需整理”。未达到 ready/published 不给虚假“开始”按钮。失败可重试，显示可操作的中文原因，保留脱敏诊断编号。

首次出现 opening 的处境可以来自已经发布且玩家可见的开局事实，不为一段欢迎文字再发独立 LLM 请求。

## 7. 统一行动入口：禁止只换皮

### 7.1 双入口、单条执行管线

新增结构化 Choice 与 UnifiedActionGateway（名字可按仓库规范调整）：

```ts
type Choice = {
  id: string;
  label: string;                 // 玩家可理解的短句
  kind: 'act' | 'inspect';       // act 才会推进；inspect 只打开资料
  sourceStateVersion: number;
  sourceBranchId: string;
  command?: ValidatedCommandRef; // 本地已知动作的引用，不允许任意函数/SQL
};

type SubmitInput =
  | { kind: 'choice'; choiceId: string; sourceStateVersion: number }
  | { kind: 'text'; text: string };
```

以上是**拟新增契约**，不是声称当前已有的 API。choiceId 在应用层重新查表验证，不能信任 UI 上传的数值和目标。提交时分配稳定 operationId，持久化接受状态后执行。

| 当前场景 | 输入类型 | 执行路线 |
|---|---|---|
| 非遭遇 | 普通自由意图 | 复用现有 V2 Planner → 本地编译 → RollRecord → Narrator → commit |
| 非遭遇 | 休息/训练等明确结构化操作 | 调用对应 Session 方法，不走一次多余 LLM 分类 |
| 活动遭遇、玩家可行动 | 结构化文字选项 | 直接解析为既有 encounter API 参数，先资格校验再执行 |
| 活动遭遇、玩家可行动 | 自由文本 | 受限 EncounterIntentProposal → 本地解析/校验 → 既有 encounter API |
| 活动遭遇、非玩家行动 | 任意新提交 | 暂不接受；保留草稿，显示“其他人物正在行动”；完成后回到玩家决策 |
| 已结束/失能且规则要求玩家选择 | 任意 | 停止自动循环，显示规则返回的合法文字选择 |

原始 V2 PlannerProposal 没有 encounter attack/rescue/retreat 等协议，不得把这些动作硬塞进其现有枚举，也不得去掉 `assertNoActiveEncounter` 来绕开战斗规则。新增遭遇意图协议作为独立受限适配器，版本化并测试，不改旧存档中的已冻结合同。

### 7.2 自由文本与多步动作

遭遇适配器可输出 attack、rescue、move、dash、guard、retreat、clarify 等**意图种类与公开目标引用**；数值、伤害、先攻、骰子、效果均由本地服务决定。只允许读玩家可见上下文。未知 key/非法目标/隐藏 ID/越权效果拒绝。

- “走近守卫并挥剑”：明确授权接近和攻击；规划不超过一次合法标准移动与一次合法主要动作。若需要疾行且会耗尽主要动作，执行前澄清“这次只能赶到近处，是否先靠近”，不能承诺同回合攻击。
- “攻击守卫”：目标唯一且已在射程内，直接执行；目标不唯一则问“哪一位”；不自动发起未表达的危险接近。
- “观察门锁”：非遭遇复用 observe/skill_check；已有技能和证据决定是否需要检定，不强行抽战斗能力。
- “说服守卫放行”：有已定义的社交检定与后果才能改变通行资格；纯 talk 只能交流，不以叙事一句“成功”绕过本地条件。
- 活动战斗中暂不支持的谈判/解谜复合动作：明确说明当前能做什么并给澄清选择，不能伪装成 guard 或空转成功。通用社会冲突引擎不在本期内。

多步动作逐步调用权威服务。前一步成功、后一步失效时，显示已发生的事实和剩余选择；不伪造原子回滚，不自动重放前一步、不把部分成功写成全部失败。

### 7.3 行动选择来源

默认 2～3 条，多于三条放“其他行动”。来自本地合法 affordance 与可见世界事实，按当前场景选取；不能固定总给“攻击/装备/任务”。调查可给观察、询问、核对已知线索；无同伴不出现“与同伴交谈”；无敌人不出现攻击。

不得为生成每屏建议增加强制 LLM 请求。未来如复用既有 Narrator 返回候选，必须单列协议变更，本期不依赖它。选择中包含人物/地点时使用公开名称；没有公开名用“附近地点”等诚实占位，不把隐藏内容或原始 ID 当文案。

### 7.4 遭遇如何开始与结束

当前 `EncounterStarter` 是从模板手动发起的“遭遇（测试入口）”；`SceneDefinition` 有 actors/zones，但没有完整敌意触发协议。**不能把删掉测试入口误认为已接通故事→战斗。**

本期最小正式路径：玩家明确选择/输入对当前公开在场角色采取冲突行动 → 应用层验证当前地点/场景、可见性、模板有效期和合法冲突资格 → 一次必要的危险取舍确认 → 以稳定 requestId 调用 `beginEncounter` → 自动处理开始阶段非玩家轮转 → 回到文字决策。该确认只发生在原意不清或重要代价需揭示时；已经明确写明后果的“与守卫交战”选项不重复确认。

需新增只读 `EncounterEntryEligibility`，从当前已发布场景 actors 与公开模板关系解析；无法证明在场/资格时不得从全世界模板列表任意生成敌人。旧世界缺少映射时显示明确能力限制并允许继续非战斗故事，不根据名字猜配模板。QA 场景须提供可验证映射，验收必须从正式文字入口进入一次遭遇。

本期不新增“LLM 说有人袭击就自动造敌”的通用触发引擎。若未来引入剧情自动遭遇，必须有独立受信事件合同与可见性/成本审查。冲突结束/撤退后回到同一正文，写入安全结束摘要、清除陈旧选择并刷新人物/地点；结局终止时不继续自动推进。活动遭遇的自由文本和正式进入/退出路径都通过后，才移除 Release 的测试入口。

## 8. 自动编排与恢复协议

### 8.1 所在层与权威边界

新增应用层 `InteractionOrchestrator`。它负责调用順序、幂等和暂停，不负责新写一套战斗计算。复用 `CampaignSession`、`EncounterService`、commit/recovery 与现有同伴 directive 策略。

自动处理：掷骰和结算、已承诺动作的合法细分、非玩家角色轮转、基于既有规则的同伴行为、日志与状态刷新。自动循环不得增加逐 NPC 的 LLM 请求。

默认不自动处理：玩家主要行动、主动撤退/投降、消耗贵重物品、支出经验或训练时间、改变队伍成员、替玩家确认线索、连续推进下一段故事。

### 8.2 状态机

```text
awaiting_input → resolving_intent → awaiting_clarification（必要时，尚未写入）
              → executing_player_step → advancing_others → awaiting_input
任何执行阶段 → paused / recoverable_error / terminal
```

进入旧活动遭遇时：读取权威当前角色。若非玩家且无待恢复的玩家选择，则接续非玩家轮转；不得开始新遭遇或重复上一玩家行动。若玩家失能且规则允许自动 NPC/同伴继续救援，可按已有状态机推进；遇玩家结局选择则停下。

正常提交后自动推进到下一玩家决策或遭遇结束；用户无需点“推进自动角色行动”。自动过程用正文状态行表达，完成后消失，不放常驻按钮区。

### 8.3 执行护栏（强制）

1. branch 级单执行者；可用现有租约/CAS 时复用。UI busy 只负责交互，不能承担一致性保障。
2. operationId 在第一次接受输入时固定；子动作 requestId 由 operationId + 子步骤序号派生，满足现有 encounter 1～96 字符限制。禁止每次渲染/重试重新用时间生成 ID。
3. 每步在调用前记录请求 ID/预期分支/预期版本；调用后读取已提交结果并推进 checkpoint。崩溃在 commit 与 checkpoint 之间时，先查同 requestId 的提交记录，不能再次造成伤害或成长。
4. 原子快照/规则版本由核心服务验证；陈旧 UI 或晚回包不得推动新分支。用户 rewind、切分支、切战役、停止或后台取消时提高 generation/fence，恢复前重新查询权威状态。
5. 冻结世界包与 Progressive binding；扩展资料完成后不能改变已冻结合同/骰点。下一安全边界才接纳新内容。
6. 初始保护值：单次非玩家推进最多 32 个机械动作，每批最多 4 步后让出 UI；墙钟上限 10 秒，网络请求另有超时。达到任一上限暂停，显示“自动处理已暂停，可继续”，不是宣布遭遇完成；记录停因。
7. 连续两步无权威进展（相同 stateVersion/当前角色/遭遇状态）立即停止并诊断，禁止死循环。每步重新读 currentActorIsPlayer，玩家到来立即停。
8. Android 后台/锁屏不持续自动替用户游玩；完成正在提交的原子动作后暂停。前台恢复处理 pending 与既有已授权步骤；不偷偷接受新的玩家选择。世界构建服务与游玩自动执行分开管理。
9. 用户可在处理中请求暂停；暂停在原子操作边界生效。若请求已提交，取消不撤销已发生结果。
10. 恢复日志不得成为第二份权威 HP/物品/关系/骰点。只保存执行协调信息；真实结果以既有提交记录为准。

### 8.4 持久化范围

Q4-01 必须提交 ADR，对现有 requestId、turn staging、recovery 与 branch journal 能力做复用核对。缺少跨进程 operation checkpoint 时允许**增量新增协调表**，不得修改既有数值规则或重命名旧表/存档标识。

协调表仅包含 operationId、branchId、baseVersion、policyVersion、已批准命令引用、子步骤 requestId、checkpoint、stopReason、fence 等。新增迁移须有旧库升级、重复启动、部分迁移失败回归。缺省无记录表示旧故事停在一个可恢复决策点，不默认执行新命令。

存档导出先到提交边界；有未完成玩家动作时提示先恢复/结束当前处理，再导出。完整已提交游戏状态仍按原格式保存；设备内操作 checkpoint 不夹带到旧格式存档。导入后从权威 committed 状态恢复，绝不续跑源设备未完成命令。若必须扩展存档元信息，单独版本与兼容 ADR，禁止静默改 schema。

## 9. 文字历史与信息安全

### 9.1 完整结果进入正文

新增 StoryEntry 只读投影，统一 committed narrative、可公开的机械结果、真实玩家 intent、重要状态变化。条目拥有稳定 ID、branchId、stateVersion、来源类型与公开内容；排序以提交序列为准，不按异步到达时间。

- 不再无条件丢弃 narrativeText 为空但 publicSummary 存在的 committed 记录。
- **publicSummary 字段名不等于已证明安全**：机械决策依据可能含隐藏能力/策略。需审查来源，先做玩家可见过滤，再投影；禁止直接把 action_contract_json、effects_json、NPC decisionBasis 全文显示出来。
- 同一玩家意图和随后的 NPC 动作可折叠成一段场景结果；仍能展开真实子事件，不能丢伤害/代价/骰点。重启/存档往返若缺分组信息可退回按提交顺序显示，不伪造用户原话。
- Narrative 失败若规则尚未 commit：显示待恢复，不宣称最终结果已落库；若已 commit：显示已提交的安全本地摘要，重试只补文案，复用既有结果。
- 不凭 intent 猜骰点；不凭最新输入补历史。读取历史 intent 需从可证明持久化来源增量只读提取。
- 表示分支的公开名称优先“主线/分支 2”；技术 ID、stateVersion、包 revision 只在诊断或存档详情。

### 9.2 非战斗与解谜

同一主界面支持三类最低验收故事：调查解谜、关系/日常、冲突/战斗。题材偏好只影响用词与可见选项，不改变本地规则、不自动增加战斗。

记录区区分：**已知事实**（当前分支已确认来源）、**角色推测**（非权威笔记，不变成事实）、**待解问题**。未来剧情、GM-only 解答、未发现证据不进入建议、Narrator 玩家上下文、全局搜索提示或图标计数。

用户“核对线索”不等于自动获得结论；回答谜题只有已有合法证据/合同支持才改变任务。对于缺少判定定义的谜题，只允许交流与保留推测，明确能力限制。不得新增万能“LLM 判断猜对就解锁”捷径。

原著事实、生成叙事与用户笔记标明来源；本地搜索无命中不宣称原著不存在。不得自动将全本查书的发现写入当前角色知识。

## 12. 兼容性与风险专项

### 12.1 旧存档和活动遭遇

建立 fixture：第三期已提交普通故事、活动遭遇停在玩家、活动遭遇停在 NPC、Narrator pending、有 RollRecord 未完成文案、已有分支/知识/物品/成长、旧主题覆盖。对同一逻辑状态升级后核对规范化快照与 RollRecord，不能以导入返回成功为结束。

旧分支进新 UI 时仅改变表现，不补造过去的意图或自动消耗玩家行动。旧 V0.1 无锁包战役继续遵循现有“可读不可按新规则前进”边界，不能为新 UI 偷偷升级规则。

D3 旧 partial 世界：构造 revealAt='1' 且无锚点的旧导入数据。优先只读查询修复或显式可恢复的新 revision 路径，证明不放开 future/GM 门控、不原地重写已发布内容；不要求有活动 Campaign 的用户删库/重导全文。若只能重导，须列明旧世界/战役保留与后续限制，不能宣布兼容 PASS。

### 12.2 重点失败模式

| 风险 | 必测反例 | 合格结果 |
|---|---|---|
| 隐藏 HUD 后无路可走 | active encounter 中输入“攻击/撤退” | 进入遭遇接口或必要澄清，不调用拒绝活动遭遇的普通 playTurn |
| 无正式战斗入口/凭空造敌 | 无活动遭遇，对公开在场角色表达冲突；另测远处/隐藏模板 | 前者合法进入且不重复生成；后者拒绝，不展示全世界敌人选择器 |
| 自动循环替玩家出手 | initiative 转到玩家 | 零额外玩家写入，立即停在可选择状态 |
| 多步部分提交 | move 成功后 kill/attack 失败 | 恢复后只重试剩余合法步骤，位置不重复变化 |
| commit/checkpoint 缝隙 | commit 后强停再启动 | 同 requestId 查已提交结果，HP/骰点/经验不重复 |
| 跨分支晚响应 | 提交后切分支/rewind | 旧结果只能归旧操作，不写入新分支；陈旧执行停止 |
| 玩家失能循环 | 玩家 critical、同伴仍活动 | 按原有 fate/救援规则推进，有界停止，不跳过结局选择 |
| 谜底泄漏 | GM/future 隐藏标记、未知 NPC 技能 | 主文、选择、资料、模型玩家上下文都不出现 |
| 一键选项误发 | 双击、旧 choice、正在处理时点击 | 相同操作只执行一次；旧 choice 明确刷新；inspect 不推进时间 |
| 无技能可用 | 开局 catalog 不足/LLM 指不存在技能 | 有解释的失败或合法降级，不发明技能、不谎称成功 |
| 空 completion | reasoning-only/超时/429/无效 JSON | 有界重试与脱敏分类，草稿保留，不重复扣费式无限循环 |
| 历史缺 narrative | 仅 publicSummary 的已提交机械操作 | 安全摘要可读，骰点一致，重启后不丢结果 |
| 返回/键盘抢空间 | 小屏战斗、键盘弹出、2×字体 | 可输入可提交、可读最近处境、无双 Modal 卡死 |

## 14. 最终验收与版本口径

### 14.1 方向硬门禁

- [ ] 非战斗、战斗都以文字正文为主，正文占比达标。
- [ ] 一条直接执行型选择只需一次点击；自由文本只需一次提交；歧义只做必要澄清。
- [ ] 默认主屏没有 zone/先攻/血条矩阵/手动 NPC/原始 ID。
- [ ] 正常自动角色轮转的用户点击数为 0，下一玩家决策自动停下。
- [ ] 普通用户无需分配属性/手选三技能/组两同伴也能合法开局。
- [ ] 调查、关系日常、冲突三类 QA 都从同一主流程可玩。
- [ ] 两部指定小说完成真实首回合、恢复与十回合轨迹；失败与预算如实记录。

### 14.2 正确性与工程硬门禁

- [ ] 原 227 项与新增反例、两处 typecheck 通过；不跳过规则/泄漏/恢复测试。
- [ ] 自动动作不重掷、不重复扣资源/成长，不跨分支执行、不伪造历史。

### 14.3 结论分层

最终必须分别回答：①第四期文字优先产品方向；②编排与规则正确性；③真实小说/模型可玩；④设备与兼容；⑤统计性能；⑥可发布性。任何硬门禁未满足，第四期整体只能 PARTIAL/FAIL/BLOCKED，不能用“代码完成”代替“完全通过”。统计性能缺样本独立标 NOT MEASURED，不伪造成已达标。

版本建议：实现阶段可使用 `0.4.0-dev.N`，所有真实对外候选发布按仓库规则递增 versionCode；只有本期硬门禁通过才考虑 `0.4.0-alpha`。本次仅编制方案，不修改版本、不构建发布、不推送主分支、不宣称 Beta。
