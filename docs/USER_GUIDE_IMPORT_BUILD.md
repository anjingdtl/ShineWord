# 小说导入与构建 · 用户操作说明

适用于 versionCode 13（0.3.0-closeout）及以后。

## 两种构建模式（统一世界构建）

导入小说 TXT 时选择模式（2026-09-30 起）：

- **循序构建（默认）**：先把全书前约 30%（按章节边界对齐）完整地抽取、映射并发布三宝书，通过同一质量门后即可开局游玩；中间约 30% 与最后约 40% 由剧情推进自动触发构建（临近阶段边界会提前预构建），不会在你未推进时后台偷偷扫完全书。世界详情页可见各阶段状态（未触发/构建中/待激活/已激活），并可随时点"转完整构建"补齐剩余阶段。
- **完整构建**：全书三宝书构建完成并发布后开局。

两种模式共用同一套抽取、证据校验、规则映射与三宝书发布质量门；切换模型需在构建前设置，进行中的任务使用创建时的冻结配置。技能与人物信息均有证据溯源；无原文数值的字段标注 rule_mapping/design_fill，不冒充原著事实。

## 导入小说

1. 首次启动在「配置你的 AI 模型」填写 OpenAI 兼容端点、模型名与 API Key（Key 只写入系统 Keychain）。
2. 进入「书库」→ 点「选择 TXT 并开始构建」，从系统文件选择器挑一本 TXT。
3. 应用会把文件拷入私有存储并流式解析（不再整本读入内存），自动分章分块，随后开始向模型抽取人物、事件与规则，最后映射并发布三宝书。

## 构建任务与进度

- 书库页顶部的**构建任务卡**显示真实进度：「抽取事实 N/M 组 · X 待重试」。所有数字来自已提交的数据库记录——退出页面、重启应用后回来，进度不会归零，也不存在虚假百分比。
- **暂停**：任务运行中点「暂停」，当前请求完成后停下，进度保存。
- **继续**：点「继续构建/开始构建」从断点续建，已完成的分组不会重复请求模型。
- **失败重试**：失败的任务卡会显示错误类别（如 等待网络）；网络/限流错误自动退避后可续建；凭据错误会提示「需要处理」，修正模型配置后再继续。
- **失败明细**：展开可看到 runId 与完成/失败计数。

## 后台与系统行为

- 开始构建后应用会启动**前台服务**并显示常驻通知（「ShineWord 构建中 · 抽取 N/M 组」）。按 Home 或切换应用，构建在后台继续。
- 通知权限被拒绝时构建仍能进行，只是看不到通知；可在系统设置中开启 ShineWord 的通知权限。
- 锁屏、系统资源紧张或系统强制停止时，应用不保证进程永生；再次打开应用后任务卡会显示已保存的进度，点「继续构建」即可续建，已付的请求成果不会丢失。
- 同一任务不会被双开：前后台同时触发时，数据库租约保证只有一个执行者。

## 旧数据说明

- 旧版本导入的世界若存在块哈希异常（同一本书所有块哈希相同），重新导入同一文件即可自愈：应用会重算正确哈希并重新抽取受影响的块，已发布的旧世界包、战役与存档不受影响。
- 已激活的源持久化在设备上：同一文件再次导入直接复用，无需重新解析；续建也不需要重新选择文件。

## 世界包导入与开局

「导入世界包」用于导入 `.shineword-world.zip` 世界包（不含小说原文）；开局、同伴招募、遭遇与存档导出/导入见应用内各页说明。
