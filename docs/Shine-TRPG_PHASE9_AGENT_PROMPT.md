三、必须落实的产品与工程行为

1. 开局增加意图和冒险提案。setup/job 在战役创建前可恢复；修改角色、时点或目标使旧候选失效。“开始冒险”在单事务中采用正确候选并创建战役，重复点击幂等。
2. CampaignIntent、CampaignPlan、CampaignRuntime 分工清楚。计划写未来机会，runtime 写实际进度，Story Memory 总结已发生经历。计划不会自动给角色知识、技能、物品、死亡或成功。
3. 整场方向与远期阶段粗规划，首阶段形成真实可玩的局面，后续按需准备。每个重要问题至少两条机制不同的路线；条件、成本、四档结果、后果和退出条件能够本地执行。
4. 推荐行动提交稳定 candidateRef/methodId。自由输入识别目标、手段、对象和证据，再由本地验证支持的操作；点选和同义文本不能因字面不一致丢失后果。
5. 主线进度、奖励、人物回应和延迟后果复用规则结算与同一个 commit/outbox。节点完成必须来自实际事件/条件；一项奖励不能因重规划、回退重放或改名重复发放。
6. 玩家可以绕路、提前解决、失败后换办法、暂停或更换目标。重大变化只重规划受影响的未来，已发生事实和已完成节点不能回滚。
7. 新增战役内容有独立作用域与命名空间，和世界内容通过统一解析器合成；不要把个人主线写回世界 canon或污染其他战役。
8. 新请求全部复用统一能力、预算、Scheduler、物理 Ledger、结构化输出和冻结体系。默认规划一次生成、最多一次修复，共享两次物理请求上限；不要在内部另套隐藏重试。
9. 规划任务可持久恢复、单飞、合并触发、有租约/fence。后台只写候选；分支稳定边界通过 CAS 采用。过期候选必须重新本地验证或标 stale。
10. 普通回合不固定新增导演/主线检查请求。权限过滤先于预算，Narrator 不接收完整秘密大纲；必需意图与当前骨架超窗时零发送。
11. 冻结的计划、材料、风格和配置身份在恢复时不能漂移；损坏信封不能改读 live DB 重冻结。已经成功的 LLM 阶段复用 artifact。
12. 回退、分叉、存档、导入恢复准确的 plan/runtime/content；父分支未来、待采用候选和知识不泄漏到子分支。
13. 沿用单一当前协议政策，在 P9-0 明确登记。旧开发数据库保留，选择新隔离测试库；不能静默清数据、迁移旧计划或维护双执行链。按 VERSIONING.md 根据实际不兼容性登记产品版本，不把“第九阶段”当版本号。
14. UI 展示真实生成阶段、当前目标、已提交进展和新的机会。空计划/占位行不可伪装 ready；无关行动不必硬推主线；不得伪造进度百分比或结局。
15. 复用已有技能、能力、物品、关系机制，至少证明一次获得和后续使用；复用当前相关 NPC 的条件反应，不扩建无限世界模拟。
