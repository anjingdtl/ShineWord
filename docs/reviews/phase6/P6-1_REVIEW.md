# P6-1 基础域建设与审查

M1/M2 实现来源成员快照、源内码点证据、SHA-256 复核和持久中文 postings。稳定页面与别名/权限分离；覆盖不足、页损坏、LRU 淘汰返回 partial，不解释为原著不存在。追加部的 s{N}- 镜像不改旧 ID。UTF-8/GBK 流式夹具接入真实导入器。

M6 扩展既有限流器为 P0～P3 队列，保留交互并发/RPM/TPM，持久资源预留但不复制请求账本。队列位于 sent 账本外侧；每个物理重试重新排队、独立记账，outcome_unknown 不自动重发。共用 endpoint bucket，429/Retry-After 与冷启动债务可恢复。

M8 实现项目绑定、三种模式、用户 CAS 覆盖、独立 P3 分析缓存、本地预算投影及完整快照。分析不能修改用户字段；重试先读冻结快照。导入快照校验表达边界、字段白名单、估算和哈希，拒绝权限/预算/未来事实指令。

M0 将所有新增表集中登记于迁移 29，包含后续段/成果域的协议存储前置；无第二事实库、计费账本或执行租约。Android 数据库装配与 UI 将在 P6-3 完成验证。

审查修复：M4 测试夹具错误调用 writeSegment 已改为实际 saveShard；暂停/停止中的已发送请求允许在同一未过期 fence 下保存结果，新的 claim 仍停止；来源跨项目测试使用独立来源以符合 schema 28 唯一成员约束；completeUnit 对已完成单元幂等，避免重复计数。后两项纳入 P6-2 回归。

验证证据：基础域定向测试见 TEST_RESULTS.md；真实 API 内容和设备性能尚不能由这些合成测试证明。凭据与小说保存在工作区私有目录，未入 Git。
