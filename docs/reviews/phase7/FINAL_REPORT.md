# Shine-TRPG 第七阶段最终报告

日期：2026-10-04（Asia/Shanghai）。方案：`docs/Shine-TRPG_PHASE7_CONSTRUCTION_PLAN.md`。基线 `main@8648d4d` → 本阶段收尾提交见 git log（P7-0/1 c700aa5、P7-2 4ee789d、P7-3/4 1a64229、P7-5 c6dc478、P7-6 c1ba09f 及门限修复收尾提交）。

## 一、实际实现了什么

1. **局面因果域**（`domain/situations`）：三值白名单条件（12 叶节点，≤24 节点深 ≤6）、幂等转换（processedEventKeys）、状态 tick（dormant→eligible→active→resolved/suppressed，deadline 冻结绝对时刻）、参考事件三态重评（suppress/apply/pending）与 actorFate 佐证门。原著 canon 与分支事实严格分离：救下的人物不会被未来原著覆盖，抑制留审计，canon 行不改写。
2. **Prepared 回合管线**：骰点后一次性本地归约（含局面运行时、因果推进、发现/任务/关系），同一 Narrator 请求输出正文+路径，分别校验独立降级，提交应用同一 Prepared 对象——奖励/后果单次写入，重放零重复。
3. **三宝书可玩内容**：Mapper 协议 v2 提案局面（真实模型已为授权小说产出高质量提案），`cleanSituation` 强门限 + 设备实证驱动的三轮接线修复（包裹条件规范化、实体/前批模板解析、actor-canon 装配重写、未提议 target 降级）；本地开局局面使 90 秒开局即可介入；城主指南"局面与动向"；world-package-4。
4. **决策点引导**：PublicSituationPacket（逐字段权限化）→ 允许候选（本地资格：技能/物品/知识/关系/存活）→ LLM 措辞（引用/长度/秘密/数字四重校验，非法即回退发布文本）→ TurnGuidanceV1 持久化（决策点绑定）；附属引导（rest/train/NPC 边界）本地同步+P1 异步升级；引导数量政策收口核心投影（normal≤3/major≤4）。
5. **移动端**：GuidanceCard（这次变化/眼下局势/下一步）、提交/预填/过期重验、UI 截断移除；save-8 存档协议（引导随档+身份重绑+旧档兼容）。
6. **版本与迁移**：V0.7.0/70000；SQLite 迁移 32（branch_situations、branch_decision_guidance、package_entries CHECK 重建）。

## 二、不同路线真实走通了什么

- **机制层（真实 session 管线，SQLite 全真）**：同起点"救同伴"双路线——救治成功→死亡参考抑制+同伴存活+计数器落库；未救→参考事件在分支成立（actor dead、局面 resolved"岳轻伤重不治"）；失败路线代价保留；无技能角色得 needs_preparation+干净拒绝。三题材夹具各≥3 结构互异办法。
- **设备层（真实 GLM-5.3-Flash +《放开那个女巫》80k 节选）**：完整闭环——导入→真实抽取（1 批）→冲突审查（罗兰身份两证并立→补充）→真实映射→开局包 world-package-4（真实锚点"序4·罗兰决定亲自见女巫"+开局局面）→开局向导（真实推荐目标）→**6 个玩家决策点旅程**：观察→引导路径点击（T2 触发依赖补建并保留意图）→连续社交情报（旅人逐步吐露后警觉收口）→需准备路径预填→自由提交→发现林向线索与情报互相印证。**每回合恰 2 次业务调用**（12/6），含 1 次真实降级兜底。
- **真实模型局面上设备**：两版局面提案（地牢中的女巫/棚屋熔铁试验；25 金龙赏金、神罚之锁、卡特·兰尼斯均为原著事实）经修复后的生产门限在主机回放中 2/2 接受并整包校验通过。

## 三、人物命运与持续后果如何验证

分支内救下→`actor_condition` 求值翻转→参考事件抑制（审计行）+存活状态随快照/分叉/存档保持；未救→命运在分支成立且后续局面按其改写。因果进度只由已提交事实/发现/已适用参考事件与已采用目录下限推进，回合数与世界时钟分钟数不推进故事序。介入窗口保证参考事件不与局面激活同回合生效。设备 80k 范围无已定死亡事件可编译（安娜处决为悬置压力），故端上命运改写留待后续分卷（复测条件见下）。

## 四、请求成本和等待时间的变化

- 普通回合业务调用**不变**：Planner+Narrator 两次（设备 6 回合实证 12 请求）；路径在同一 Narrator 请求内输出。
- 设备每回合结算 18–20 秒（对照第六阶段设备轮回合量级一致；正式对照需固定全部条件重测，见未验项）。
- Token（账本实测）：6 回合旅程 input 24,346 / output 3,364 / cached 1,280；世界构建全程 10 请求 input 59,150 / output 22,217。
- P1 附属引导零阻塞；未观察到请求风暴；账本唯一性沿用（logical id `guidance:{branch}:{decisionPointId}`）。
