# G2 review: local Chinese source search

**Stage:** implemented, reviewed, fixed, and regression-checked

**Date:** 2026-09-29 (Asia/Shanghai)

## Result

- Added a dictionary-free Chinese tokenizer: Han runs produce overlapping bigrams, one-character runs are filtered by a small stop list, and ASCII letters/digits remain whole terms. Normalization uses explicit punctuation ranges and code-point helpers, without relying on Unicode-property regular expressions or SQLite's `unicode61` segmentation.
- Added an incremental local inverted index over bounded paragraphs, entity-name/alias matches, BM25-style ranking, and same-chapter adjacent-paragraph prefetch. Paragraphs are capped at 1,200 code points; queries at 24 distinct terms; results at 8 hits; prefetch at 4 paragraphs (the application lookup currently requests 2).
- Added `LocalSourceSearchService`. It verifies the source is active, reads persisted chunk ranges one at a time, checks each range length, and never assembles the full novel in memory or sends search text to a model. The service is invoked only by a later foreground lookup/build request; it is not part of opening readiness.
- Search results with no local match say only that this index has no match. They do not claim that the source lacks the fact.
- Added an FTS5 runtime capability probe after SQLite migrations. Host Node SQLite FTS5 is available in this environment; Android's bundled SQLite result remains unverified because no Android target is connected. The probe reports capability only and does not select a Chinese tokenizer.

## Cache and bounds

The process-local LRU retains at most two indexes. Keys include source identity, raw and normalized source hashes, tokenizer version, and the exact sorted entity-name/alias catalog, so a re-import or alias edit causes the next lookup to rebuild. Each persisted source chunk is read and indexed in order, then released before the next range. On process restart the index is rebuilt on the next lookup; it is not persisted as novel text or an index database.

## Review and verification

Review found that the initial implementation used Unicode-property regular expressions and tried to expose a batch-only builder. Those were replaced with explicit punctuation handling and an incremental builder. The source-range service now rejects incomplete chunk reads. Regression coverage checks Chinese/Latin token behavior, alias resolution, incremental/batch parity, unknown terms, astral-character offsets, chapter boundaries, bounded passage reads, cache invalidation, and both supported/unsupported FTS5 responses.

## Limits

This stage does not start whole-book indexing before the first turn and does not yet wire prioritization/cancellation into the game action pipeline; that belongs to G3. The in-memory index is rebuilt after process restart. Android FTS5 capability and device-level indexing latency need a Release build on a connected device; neither is represented by the host SQLite test.
