# G3 review: demand-driven preparation queue

**Stage:** implemented, reviewed, fixed, and regression-checked

**Date:** 2026-09-29 (Asia/Shanghai)

## Result

- Added one serial `ProgressiveBuildQueue` with strict priority: current action, near-domain prefetch, then active book lookup. A new current-action task cancels lower-priority active work. While Planner/Narrator is using the foreground provider, background queue work is paused.
- Connected current-action retrieval to `CampaignSession.playTurn`. It searches only exact evidence spans referenced by entries already projected to this player and visible at the campaign's story-time anchor. GM-only, unrevealed, conflict, speculative, and unreferenced future facts cannot broaden Planner's source scope.
- The Planner receives at most three matching paragraphs, each capped at 1,200 code points. A failed or empty local lookup does not block the turn and does not claim the fact is absent.
- After a successful commit, the session queues a local lookup for the next location and current goal. Its `stateVersion` fence discards stale work. Active book lookup is available through the lower-priority service path and uses the same published, time-visible citation scope; it does not search unreviewed future source for Planner context.
- Queue bounds: one active task, at most 24 queued tasks, at most three input passages / 3,600 code points, 1,200 output tokens per physical request, two physical requests per task, and three requests / 3,600 reserved output tokens per ten-turn state-version window. Identical active tasks are coalesced; the bounded process-local queue result cache remains available for immutable builders. Source lookups disable that cache so the search service always checks its source, range, tokenizer, and alias fingerprints.
- Source index cache keys include allowed source ranges, source hashes, tokenizer version, and entity aliases. Scoped lookup reads only those ranges. The full-source local index is available only to an explicit unscoped lookup request and is not part of the turn path.

Budget-window boundary coverage confirms the first ten state versions share one budget window.

## Limits

The near-domain task currently warms the safe local search cache; it does not spend a model request or publish a content delta. Delta publication, branch/stateVersion content manifests, and review-on-conflict are G4. The initial G3 review had no player-facing active-book lookup; the follow-up below adds one. Android first-ten-turn wait and full-source index latency remain unmeasured because the Release opening did not publish a package.

## Follow-up: explicit “随探索补齐” lookup

- Player mode now exposes a local search card for the selected book. Search is user initiated, limited to an 80-code-point query and at most three bounded passages, and does not call a model. The lookup indexes the active imported source on demand; a first full-source search can therefore include local indexing time.
- Results are persisted as a fixed-template immutable delta containing exact source quotes only. Entries are `discoverable` with a source-lookup confirmation policy. The UI receives IDs and a count, not passage text. Only the explicit “记录为角色已知” action records discoveries on the selected campaign branch.
- Unconfirmed excerpts are withheld from the player book projection and Planner evidence ranges. Ordinary delta publication remains restricted to citations already visible on that branch. A no-match result says only that the local index has no match.
- Confirmation uses a state-version fence and exact chapter/range/hash replay. Save and rewind tests verify that the immutable delta remains available while later character knowledge and expansions disappear from a rewind before confirmation. No provider call is made by lookup or confirmation.
- Full `npm test`: **224/224 passed**. Core and mobile typechecks passed. On the v15 Release, the world-books screen showed the lookup card for a world without an associated campaign and correctly disabled the action with an explicit campaign requirement. The real-novel opening failed before publication, so no campaign-scoped lookup ran on device. Device indexing latency remains unverified.
