## 2. 本轮关闭与补强

### 战斗事务、奖励与恢复

- 遭遇开始、玩家/自动角色攻击、移动、疾行、援救、跳过、撤退、结束和临时敌人清理统一经 `commitResolvedTurn`/`commitAtomic` 提交。权威角色状态、遭遇/区域图、先攻游标、轮数、行动额度、世界钟、事件、奖励投影和完整快照同事务写入；攻击骰先持久化。
- `R2-01` 正式故障注入现在让攻击成为最后一击，并在 SQLite 快照写入边界失败。失败后版本、HP、游标、事件、练习奖励和掉落均不前进；导入保留原投骰；重试在一个事务中提交伤害、清理、奖励和快照；重复 `requestId` 不重复伤害/奖励，也不重掷。
- 对手模板现在可声明已发布物品条目 `lootItemIds`。发布阶段校验每个引用都指向 item；最后敌人倒下时按战役锁定的世界包版本生成一次，并把物品归给存活玩家角色。战斗撤离、失能退场不生成该击杀掉落；唯一条目已有归属时跳过。
- 完整历史包含遭遇与战场状态。战斗前、开始后、移动后、已投骰未提交、攻击后、援救后、战斗中分叉/存档、撤退结束后的回归均覆盖；结束后的历史不会复活临时敌人。

### 行动经济、同伴与新入场

- 玩家控制与自动控制明确区分；AI 同伴不会被当作玩家角色。玩家不能替同伴直接攻击、移动或跳过；同伴可持久配置跟随、支援、保护、节省资源、撤退指令。策略只选择合法移动/攻击/援救/撤退/戒备，模板撤退阈值和攻击射程由卡片持久化；NPC 与玩家撤退都要求当前区域连到显式场景出口，不凭空生成出口；攻击提交结算练习奖励。
- 队伍 API 与开局 UI 均限制最多两名同伴；正式回归覆盖服务端超额拒绝。该约束不等于招募条件/关系阈值已经实现。
- 遭遇参与者保存 party、hostile、neutral 三种阵营。中立角色拥有冻结先攻槽，默认只作已记录的戒备行动，不自动攻击任一方；SQLite、遭遇视图、完整快照与重载均保留 neutral。正式回归验证了持久化与无骰无伤害。
- 每人每轮最多一次主要行动与一次标准移动；疾行支付主要行动；援救消耗主要行动；玩家跳过、自动移动/攻击/撤退、失能槽跳过共用同一轮次推进。轮末时钟只随完整轮统一推进 6 秒。
- 新增遭遇中队伍角色延后加入接口与 UI 入口。加入提交先记录为 pending，不插入当前先攻；轮次翻转时在同一事务加入先攻、位置和演员状态，保留原演员的冻结顺序。pending 状态随完整快照及存档导入恢复。正式回归从 battle 中途加入、导出/导入，再跑到下一轮，检查只入场一次且两种行动额度均未用。
- 延后入场标记复用遭遇 JSON 信封与完整快照字段，没有增加 SQL 列；旧存档/旧信封缺少该字段时按空队列读取。既有 SQLite 迁移仍由全量测试覆盖。
- 原方案 §11 的招募条件/关系阈值、分队/重新入队与退出/失能/死亡风险事件、同伴视角下的秘密知识隔离仍未闭合。已完成的指令策略和 neutral 自动戒备只关闭对应子项，不能替代这些剩余范围。

### 第二轮复现注入质量

旧第二轮脚本曾 monkeypatch 已不再使用的 `saveEncounter`，会显示 `PASS` 但没有注入故障。本轮已把该处改为 `snapshots` 表触发器，严格要求故障真实发生，并断言故障后没有部分事件/奖励、先前骰记录存在、版本/HP/游标不变、重试与重复请求幂等。最新输出包含 `faultRaised=true`、版本 `2→2`、HP `6→6`、骰调用次数 `3→3`，5/5 检查全部通过。
