## 2. 第二轮缺陷关闭证据

### R2-01：战斗权威状态统一提交

遭遇开始、移动、疾行、攻击、援救、跳过、NPC 行动、撤退、结束、奖励和临时演员清理统一进入战斗 Action/UnitOfWork。角色资源、遭遇与战场、轮次/先攻游标、移动及主要行动额度、世界钟、事件、奖励与完整快照由同一事务提交；投骰在提交前持久化。

最新第二轮复现将失败注入 SQLite 快照写入边界：真实抛出故障后版本仍为 `2→2`、HP `6→6`、游标不变、部分事件/奖励为 0；已持久化骰调用数保持 `3→3`。使用同一请求重试只提交一次，重复请求幂等，不重掷。R2 原脚本继续保留，故障点与断言均有效。

### R2-02：遭遇历史、分叉和存档

- 完整快照现在包含遭遇状态和战场状态；存档升级到 `shineword-save-5`，导出分支的历史快照；恢复时重映射 campaign/branch 引用，并写回历史分支快照。旧 v4 仍可读，但只具备其本身提供的当前状态，不伪造历史。
- 正式回归覆盖战斗开始、移动、已投骰未提交、攻击、援救、撤退/结束、分叉、导入和结束敌人清理。R2 复现覆盖战斗中分叉及存档游标/战场恢复。
- 修复世界包多跳导入的本地 ID 不同问题：带内容哈希的保存局按不可变包内容哈希和修订匹配；没有内容哈希的旧保存局仍使用直接来源匹配，不猜测依赖。
- 实际 UI 保存局在源端为 v5、历史快照 v0–v5、含一个活动遭遇。5558 导入世界 ZIP 后再导入保存局，攻击行动位置与战场状态恢复；杀进程后打开分叉，v4 玩家行动位恢复。随后从该导入局导出 v9（历史 v4–v9），清理 5558 应用数据后再次导入同一 ZIP 与 v9 保存局，生成新 campaign，仍恢复活动遭遇、第 3 轮与同一先攻行动者。

### R2-03：行动经济与轮末时钟

每角色每轮只有一次主要行动和一次标准移动；疾行消耗主要行动；跳过、援救、NPC 行动、失能槽和轮末翻转走统一的先攻推进路径。完整轮结束统一推进 6 秒，不依赖最后一名行动者的动作类型。

正式回归覆盖第二次标准移动拒绝、疾行成本、援救主要行动、玩家跳过、自动角色动作、失能跳过和延迟加入。5558 UI 在活动战斗实际完成两轮后，数据库 `clockSeconds=12`、遭遇第 3 轮；UI按整分钟显示为 0 分钟，是显示精度，不代表没有记秒。短休后数据库为 1812 秒，界面显示 30 分钟。
