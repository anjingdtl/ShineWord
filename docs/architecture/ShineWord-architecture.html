2. 世界构建流水线

关键点：模型侧只被允许输出原著原文片段（verbatim 引文），字符偏移的解析与证据位置的校验全部在本地完成；worldBuildStore 以 build_run/build_unit 记录抽取单元状态，使构建可中断续跑。

3. 回合结算闭环与 LLM 权限边界

排序上最关键的一点：RollRecord 在读模型之前就已经持久化。因此 Narrator 失败、进程被杀或设备重启后，同一回合会复用同一颗骰子，只补叙事——这使「确定性」不依赖模型可用性。

6. 关键设计决策

本地优先游戏状态全部落在设备 SQLite；断网时确定性行动仍可结算。唯一网络请求是用户自行配置的 OpenAI 兼容端点。无遥测。

确定性骰点骰点由本地引擎以 Android SecureRandom 拒绝采样产生，先持久化后叙事；resolveOrReuseRoll 保证同一行动永不重掷。

LLM 权限边界Planner 只能产出 ActionContract（禁止骰点、结果、数值等权威字段），由 domain/turns/contracts 严格校验；Narrator 不得更改已冻结的结果等级。

正史不可变 + 分支覆写共享 canon_events 不被分支改写，分歧写入 branch_canon_overrides，避免同一原著的两个战役互相污染。

渐进式构建开局只构建当前行动与近域内容，其余由 progressiveBuildQueue 按优先级增量产出 ProgressiveDeltaPackage，绑定到分支的 BranchContentManifest（内容版本可追溯）。

密钥安全API Key 只进系统 Keychain（WHEN_UNLOCKED_THIS_DEVICE_ONLY），SQLite/AsyncStorage 仅存 keyRef；导出存档时递归扫描禁入键（apikey / key / secret / token / authorization），命中即抛错。
